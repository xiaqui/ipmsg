# Android・Windows・将来iOS 共通ファイル転送構想（設計のみ）
2026-10-16。**現行v1はTEXTとACKのみ。ファイル転送は未実装で、パケット定義も未確定。**
- 対象: 画像、PDF、APK、ZIP、任意のファイル、複数選択、進捗、中断/再開、送信履歴、受信ファイル保存先選択。
- 承認済みピア間でのみ受け付け、既存ID/指紋/相互認証/暗号化を再利用。無断実行・自動APKインストールは禁止。
- 候補: transferId、fileId、ファイル名（パストラバーサル禁止）、MIME、byte数、SHA-256、チャンク連番/オフセット、暗号化チャンク、保存確認、最終ハッシュ検証、再開時の欠損チャンク指定、キャンセル、上限/空き容量/転送失敗理由。
- AES-GCMのnonceを鍵ごとに重複利用しない。鍵更新、ストリームサイズ、転送時のメモリ上限を設計。ファイル/添付型と本文v1の互換・能力交渉を先に決める。
- AndroidはSAF/Content URI、Windowsは選択保存先、iOSはFiles/共有シートの制限を考慮。
- 受け手の承諾、上書き回避、ダウンロード中一時ファイル、ハッシュ照合後の確定、ファイル名サニタイズを必須とする。
- M6前にプロトコル拡張仕様と正常/改ざん/切断/再送/大容量/多ファイルの共通テストを作成。**仕様確定や実装完了とは報告しない。**
